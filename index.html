Chartwise

source↗

A clinician uploads a visit recording or transcript, and recordings are transcribed locally with Whisper. Chartwise pulls the patient's history from a FHIR server, has an LLM draft a SOAP note, checks it for medication errors, and queues it for review. The approved note is filed back to the patient's record, and every step is logged. All patient data is synthetic.

pipeline — pick a stage

01 · Java · Upload

# what it does

The Spring Boot service stores the encounter (transcript encrypted with AES-256-GCM) and an outbox event in one database transaction, then returns 202 Accepted. A relay publishes the outbox to Kafka.

# when it fails

Both rows commit or roll back together, so an encounter can never exist without being processed. Intake only writes two rows, so during a simulated LLM outage uploads were still accepted at full rate.

02 · Kafka · Event bus

# what it does

Carries encounter.created, note.drafted and note.approved, keyed by encounter ID. Events carry IDs only: the transcript stays behind an audited API and never enters Kafka.

# when it fails

Messages that keep failing go to a dead-letter topic and show up as a DRAFT_FAILED state an admin can retry, instead of silently disappearing.

03 · Python · Note worker

# what it does

Fetches the draft context for the visit (no names or identifiers), drafts several notes at once, validates the SOAP structure, and publishes note.drafted.

# when it fails

Offsets are committed only after Kafka acknowledges the draft, and only up to the first unfinished message per partition. Killing the worker mid-stream across 200 encounters left 0 lost and 0 duplicated notes.

04 · Go · LLM gateway

# what it does

The only path to the LLM: Redis token-bucket rate limiting, retries with jittered backoff, and a circuit breaker in front of the Claude API, served over gRPC.

# when it fails

The gateway fails fast while the worker waits. In a simulated 60-second provider outage the breaker opened in 8s, the backlog peaked at 153 and drained after recovery, and 0 drafts failed.

05 · Python · Safety check

# what it does

Flags medications in the draft that appear in neither the patient record nor the transcript, drugs started despite a recorded allergy (penicillin allergy, then amoxicillin), and doses nobody stated or that the clinician corrected.

# what it catches

Caught 100% of 728 injected drug, allergy and dose errors with 0 false positives on 544 clean drafts. The limits are measured too: injected drugs come from its own drug list, and doses are checked in mg and mcg, not frequency or route.

06 · React · Review

# what it does

Shows the transcript and draft side by side. Every save is a new version, with a diff against the original AI draft.

# guardrails

Only clinicians can approve, and only the version they are looking at. Every view, edit and approval goes to an append-only audit log, enforced by a Postgres trigger.

07 · FHIR · Filing

# what it does

The approved note is written to the patient record on a HAPI FHIR server as a DocumentReference, and the encounter becomes FILED.

# when it fails

A FHIR write cannot join a database transaction, so filing first does an idempotent conditional create keyed by encounter ID, then marks the encounter filed. A retry cannot file the note twice.
